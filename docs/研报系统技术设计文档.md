# 研报系统技术设计文档

## 1. 系统概述

研报系统是一个用于处理金融研究报告中 PDF 文件的自动化流水线系统。系统将研报 PDF 解析为结构化的 Markdown 文本，进行智能分块处理，最终存入 Milvus 向量数据库以支持 RAG（检索增强生成）应用。

### 1.1 核心功能

- **PDF 解析**：使用 Mineru 将 PDF 转换为 Markdown
- **图片/表格分析**：通过 LLM 分析图片和 HTML 表格内容
- **智能分块**：基于 Markdown 标题结构进行语义分块
- **上下文增强摘要**：生成包含报告上下文的增强摘要
- **双向量检索**：同时支持内容向量和摘要向量的检索
- **重复处理支持**：同一研报可重复处理，自动覆盖旧数据

### 1.2 技术栈

| 组件 | 技术 |
|------|------|
| 框架 | FastAPI + SQLAlchemy (异步) |
| PDF 解析 | Mineru (vlm-http-client) |
| LLM | DashScope / 通义千问 |
| 向量数据库 | Milvus |
| Embedding | BAAI/bge-large-zh-v1.5 |
| 任务队列 | Celery + Redis |
| 配置管理 | YAML + Pydantic |

## 3. 处理流水线设计

### 3.1 流水线框架

系统采用**状态驱动的流水线框架**，每个处理步骤根据当前记录状态决定是否执行。

#### 3.1.1 核心类

```python
# app/core/pipeline.py

@dataclass
class StepResult:
    success: bool           # 是否成功
    message: str           # 结果消息
    data: Optional[dict]    # 额外数据

class PipelineStep(ABC):
    name: str                           # 步骤名称
    target_state: Optional[str]          # 成功后目标状态
    optional: bool = True               # 是否可选
    
    async def can_execute(record, context) -> bool:
        """检查是否可以执行"""
        
    async def execute(record, context) -> StepResult:
        """执行步骤"""

class Pipeline:
    steps: list[PipelineStep]
    
    async def execute(record, context) -> dict:
        """执行流水线"""
```

#### 3.1.2 流水线执行逻辑

```
Pipeline.execute():
  1. 遍历所有步骤
  2. 调用 can_execute() 检查前置条件
  3. 执行步骤，返回 StepResult
  4. 成功时更新 record.process_status
  5. 可选步骤失败继续，非可选步骤失败停止
  6. 返回执行结果汇总
```

### 3.2 处理步骤

| 步骤 | 类名 | 目标状态 | 可选 | 说明 |
|------|------|----------|------|------|
| 1 | `MineruParsingStep` | `pdf_analyzed` | 否 | Mineru PDF 解析 |
| 2 | `ImageTableAnalyzeStep` | `integrated` | 是 | 图片/表格 LLM 分析 |
| 3 | `MarkdownChunkingStep` | `chunked` | 否 | Markdown 分块 + 上下文摘要 |
| 4 | `MilvusStorageStep` | `chunked_to_db` | 否 | 向量入库 |

### 3.3 状态流转

```
┌──────┐
│  no  │  ← 初始状态
└──┬───┘
   │ MineruParsingStep
   ▼
┌─────────────────┐
│  pdf_analyzed   │  ← PDF 解析完成
└────────┬────────┘
         │ ImageTableAnalyzeStep (可选)
         ▼
┌─────────────────┐
│  integrated     │  ← 内容整合完成
└────────┬────────┘
         │ MarkdownChunkingStep
         ▼
┌─────────────────┐
│   chunked       │  ← 分块完成
└────────┬────────┘
         │ MilvusStorageStep
         ▼
┌─────────────────────┐
│   chunked_to_db     │  ← 最终状态
└─────────────────────┘
```

## 5. 上下文增强摘要设计

### 5.1 设计背景

传统 Chunk 摘要缺乏上下文信息，导致检索时无法理解内容在整篇报告中的位置和意义。

### 5.2 上下文增强摘要方案

采用 Anthropic 提出的 **Contextual Retrieval** 方案：

```
┌─────────────────────────────────────────────────────────────────┐
│                    上下文增强摘要生成流程                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 生成整篇报告摘要                                             │
│     generate_report_summary(full_content)                         │
│                    │                                              │
│                    ▼                                              │
│  2. 对每个 Chunk 生成增强摘要                                     │
│     generate_contextual_summary(                                  │
│         chunk_content,      // Chunk 原始内容                     │
│         report_summary,     // 整篇报告摘要                       │
│         header_path,       // 标题路径                           │
│         report_title,      // 报告主题                           │
│         chunk_index       // Chunk 索引                          │
│     )                                                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 Prompt 设计

#### 整篇报告摘要

```markdown
请为以下研报内容生成简洁摘要。

要求：
1. 概括报告的核心主题和研究结论
2. 保持客观中立
3. 直接返回摘要文字
4. 摘要内容不超过 300 字

研报内容：
{content}
```

#### 上下文增强摘要

```markdown
这是一篇关于「{report_title}」的研报分析。

【整篇报告摘要】
{report_summary}

【当前段落位置】
{header_path}（第 {chunk_index} 个段落）

【当前段落内容】
{chunk_content}

请用 50-100 字概括这段内容在整篇报告中的核心贡献，直接返回摘要。
```

class ImageTableAnalyzeStep(PipelineStep):

class ProcessStatusEnum(str, Enum):

for i, chunk in enumerate(chunks):
    chunk["title_embedding"] = title_embeddings[i]

## 11. 注意事项

### 11.1 重复处理

- 使用 `chunk_uid` 作为唯一主键
- 重复处理同一研报时，会先删除旧数据再插入新数据
- 需要手工删除旧 Collection 以应用新的 Schema

```python
# 删除旧 Collection
from pymilvus import utility
utility.drop_collection("research_report")
```

### 11.2 并发处理

- 各步骤内部使用 `asyncio.Semaphore` 控制并发
- `analyze_image/analyze_html_table` 并发限制: 5
- `generate_summary/extract_related_stocks` 并发限制: 10

### 11.3 错误处理

- 可选步骤失败会记录日志但继续执行
- 必需步骤失败会中断流水线
- 所有异常都会被捕获并记录
